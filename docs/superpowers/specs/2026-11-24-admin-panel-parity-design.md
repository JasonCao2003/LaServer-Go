# 旧管理面板功能复刻设计

设计草案 · 2026-11-24 · Go 基线 80c868c

## 目标与基线

管理员应能分别管理 API 和房间进程，维护玩家数据，诊断一次游戏请求，并在接收机器上确认一次更新。沿用现有 Go Web 面板的登录、服务概览和好友操作。复刻以管理员操作结果及游戏内可见效果为验收依据。新实例可以使用空 SQLite。

截图展示了顶部工具和十个页签，其中展开的是「更新接收」。其余页面的操作来自并列旧仓库 apps/admin 下的 admin_panel_client.py、friend_control_panel.py、game_control_panel.py、magic_control_panel.py、ugc_control_panel.py、other_control_panel.py 和 api_response_manager.py。现有 [Go 面板路由](../../../services/admin-panel/internal/panel/server.go) 已提供登录、退出、健康概览、按 ID 查询及双向好友操作。以下内容为拟开发范围。

## 页面与验收

| --- | --- | --- |

## 账号管理页详设

按补充截图布置三处操作区。顶部从左到右为搜索框、搜索、刷新、「自动授权」与「无库就建号」开关，右侧为账号统计。中部是可多选的账号表。底部第一行放单账号操作、数据浏览和后台接口管理，第二行放批量操作及「新建账号全解锁」。页脚显示本次加载数量。三个策略开关从 API 读取实际值，截图中的「开」仅代表拍摄时的配置。

**账号表**按顺序展示用户 ID、设备名、平台、版本、在线状态、封号状态、截止时间、注册时间。平台和版本优先读结构化字段，缺失时从 User-Agent 解析。正常账号截止时间为短横线，限时封禁显示当地日期和分钟，永久封禁显示「永久」。旧面板用淡黄色标识自动授权创建的账号；Web 版同时给出文字标记，多选状态使用独立的选择框。

**在线与统计**沿用旧源码的请求活跃口径。最近 300 秒内有 API 请求算在线，正好 300 秒仍在线，缺少记录算离线。页面提示该值反映最近请求活动，玩家是否在房间内由房间服务另行提供。总数、封禁数取全库统计，未授权数和在线数取本次查询结果，其中已封禁账号不计入未授权数。Web 版在统计旁注明范围，分页时按完整匹配集计算。

| 已选账号数 | 可以执行的操作 |
| --- | --- |
| 0 | 搜索、刷新、数据浏览、后台接口管理及全局策略仍可用。单账号与批量操作均禁用 |
| 1 | 删除、转移数据、推送全解锁、全物品。封号与解封根据封禁状态二选一，授权与取消授权根据授权状态二选一 |
| 2 个及以上 | 启用批量封号、批量删除、批量授权、批量取消授权，禁用单账号操作。提交前显示所选数量和目标账号 |

**转移数据**以当前账号为源，由管理员输入目标 ID。确认页同时展示两个 ID，明确目标现有数据会被覆盖、源账号会被删除。源和目标相同时拒绝提交。API 在事务内完成转移，失败时保留双方原始数据。

**验收示例**使用虚构账号 A、B，设备名相同但 ID 不同。按 ID 搜索 A 时应只显示 A，全库总数仍为 2。取消选择、单选 A、再同时选中 A 和 B，逐步验证上表。把 A 的最近请求时间固定在 300 秒和 301 秒前，分别验证在线与离线。用隔离存档测试 A 转移至 B，先取消并核对双方存档，再确认并检查 B 的存档、A 的移除及审计记录。

## 顶栏与诊断工具

- **网络设置**。区分 UDP 监听、向客户端公告的地址、局域网联机开关和 UPnP 映射。展示协议、内外端口、映射归属和路由器结果。映射失败时仍可使用局域网地址。防火墙调整需要操作系统权限，展示执行结果。
- **HTTP 请求响应查看**。按时间、路由、状态、测试账号和请求 ID 筛选有界记录，查看耗时和脱敏后的请求及响应。编辑响应覆盖单独入口，只开放指定开发路由。精确匹配路径，账号覆盖优先于全局，停用后回退，全程保留身份及权限检查。
- **UDP 接口响应查看**。由房间进程提供方向、协议族、消息类型、房间、长度和处理结果。未知消息显示原始类型编号。以一次测试入房串起请求与响应，默认隐藏入场凭据。
- **热更新接口**。列出 API 和 UDP 可更新项、当前版本和生效方式，支持筛选、选择和推送。在 Go 中，配置和资源可由所属服务校验后重新加载，已编译的处理函数随对应服务版本发布并单独重启。

## 更新接收与发布

设置页分列接收监听地址和端口、API 与 UDP 安装或资源目录、后台重载地址及访问凭据。显示可复制的局域网地址，外部地址按显式配置或隧道状态显示，支持重新检测或生成地址。旧面板的 9527 是接收端口示例，8443 是游戏 API 示例，两者分别配置。Web 管理页继续使用回环监听，接收器独立启停。

1. 发送方连接指定接收器，读取版本和能力清单。拟采用 Go 版清单协议，历史 Python 推送端互通需单独验收。
2. 发送带批次 ID、目标服务、基准版本、项目清单、大小、摘要及签名的更新包。接收方验证来源、版本及目标目录，将文件写入暂存区。重复批次返回原状态。
3. 管理员核对差异、目标和是否需要重启后确认。可重载资源一次切换到新版本，程序更新保留上一版本，分别检查进程健康和业务探测。每服务记录成功、失败或回滚结果。
4. 拒绝、断线和校验失败保留当前版本。应用中断后依据持久化批次记录恢复。验收包括正常发布、重复推送、错误摘要、目录越界、重启探测失败与回退。

## 服务边界与写入合同

| 所有者 | 接口设计与数据归属 |
| --- | --- |
| admin-panel | Go 模板和表单，复用会话、Host 校验及现有写操作保护。只向配置的上游请求。进程启停走本机受管程序清单，目录和参数由本机配置指定 |
| api-server | 管理接口负责账号、好友、道具、公告、UGC、IP 规则和对应 SQLite 事务。复用已实现的业务规则。新增表或索引由 API 迁移管理 |
| room-server | 通过受认证管理接口提供在线状态、UDP 事件和运行配置。房间离线时显示不可用，API 和面板仍可独立运行 |
| 本机更新接收器 | 保管暂存包、已信任发布密钥、当前及上一版本和批次记录。访问凭据与浏览器会话分离 |

建议查询接口支持分页、筛选和稳定 ID。单项修改提交目标、预期版本和变更字段。发放、转移、删除及批量写入另带操作 ID。API 返回操作 ID、实际影响、逐项失败原因及当前版本。批量操作先预览并冻结目标集，确认后处理。超时可按操作 ID 查询。审计保存时间、操作者、目标及变更摘要，过滤凭据和玩家敏感数据。SQLite 仅由所属服务访问，无需 Redis 或 MySQL。

## 交付顺序

1. **控制台基础**。保留已有好友流程，增加账号检索、API 与房间独立启停、日志和只读诊断。以一个服务离线时另一个仍可管理为验收。
2. **玩家与内容**。实现公告、账号、IP、游戏、魔法、UGC 及其他数据操作。每类至少覆盖一次正常提交、失败恢复和客户端回读，批量写入额外验证重试。
3. **联机运维**。接入房间状态、UDP 诊断、局域网和映射，使用两台客户端验证同房与在线推送。记录实际客户端版本。
4. **更新链路**。先交付本机资源重载，再交付两台机器之间的发送、待审、应用和回滚。分别验证 Windows 与 Linux 的进程和文件切换。

交付记录按操作区分「已实现」「服务联调通过」「游戏内验证通过」，注明服务版本、客户端版本及复现步骤。上线前需确认是否要求与旧推送端互通，以及哪些配置项经运行中的服务验证可热加载。

### 游戏运营九个子页

以下项目对应 game_operations_panel.py。运营配置由 API 发布带版本的快照，预览显示变更范围，修改失败时继续使用上一版本。

| 子页 | 操作 | 验收 |
| --- | --- | --- |
| 商店控制 | 重载商品列表，编辑价格、货币种类和上架状态，统一保存 | 客户端列表和实际购买扣款与配置一致 |
| 活动控制 | 按关键词与活动类型筛选，增删日程，单独或批量启停，设置开始时间与持续秒数。烛火含总开关、两组独立设置、全部开启或每日随机、数量及持续时间 | 关总开关停用两组，模拟跨日验证随机日程与生效窗口 |

| 账号默认数据 | 编辑新账号初始化货币，重新载入并保存 | 新账号读到新配置，已初始化账号余额保持原值 |

| 每日任务 | 分开编辑普通与季节任务池，新增、删除、随机选取四项，分别设置领奖货币 | 模拟有季节和无季节两种状态，核对任务池和到账货币 |
| 任务树 | 查看上游响应，编辑或删除本地响应覆盖，校验 JSON 后保存 | 有效覆盖生效，非法配置拒绝，删除后回到对应基线 |
