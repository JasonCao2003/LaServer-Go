# LaServer-Go UDP 房间服务开发设计

日期 2026-11-23 · 设计草案

依据 [开发交接](../../archive/records/room-server-handoff.md)、[Go 重构设计](2026-11-11-go-rewrite-design.md)及当前源码。本文定义开发边界、拟议接口和验收门槛。

## 1. 范围与现状

本次采用全量一次性交付。以旧实时服务源码、启用配置和可复现实测行为为基线，盘点协议、版本配置与玩法，在同一个可发布版本交齐并统一切换。0.1.8 与 0.3.11 的实际 APK 均须完成端到端验收；旧服务声明支持的其他构建也纳入兼容矩阵，明确现有覆盖和本次验收证据。API 负责账号、会话、好友权限与 SQLite，room-server 负责实时状态与协议适配，两者独立构建、启停和部署。MQTT 与 WebSocket 继续走各自的接口，并纳入相关玩法的联调验收。

当前 room-server 只有 README 和 Go module。API 的 Discover 先认证 HTTP 请求，再保存分配并返回公告地址和签名字段。现有签名由公告地址与固定字符串计算，不能证明 UDP peer 的身份。旧严格 JoinGame codec 读取 UUID、joinToken 和 joinSignature，字段来源及其与 API 会话的绑定仍待验证。MuMu 0.1.8 已观察到发现接口 200，UDP 与实际入房均未验证。历史发现接口 500 单独调查。

## 2. 全量迁移与传输选择

按协议族、构建特例和玩法建立覆盖表。每行记录旧实现入口与启用条件、客户端指纹、收发方向、报文和通道语义、状态变化、异常回退、样本、自动化与客户端验证结果。同一场景的多个版本差异分别登记。旧服务用于差分和回滚，存在明确缺陷的行为单独记录处理结论。

| 范围 | 必须盘点的内容 |
| --- | --- |
| 协议与版本 | 旧 PacketIds、PacketDispatcher、全部 packet codec、versionMatrix 与引擎特例。覆盖入离房、时钟同步、关卡更新、移动与取消、GameMsg、NetLevelData、快照与 ACK |
| 实时玩法 | 房间分配、好友入房、名册与可见性、移动与状态同步、快照与权威切换、自然过图、重连、分房/合房及旧服务支持的转移行为。按旧 GameMessageService 等入口逐项盘点音乐、交互与消息子类及其真实路由 |
| 工作流与运维 | 地址发现、认证、在线查询、管理与必要观测、停机和异常恢复；涉及 MQTT 或 WebSocket 的流程须跨接口验证 |

本次设计以目标客户端与服务直接连通、各玩法通过验收为传输选型门槛。此项更新旧设计中的 ENet 实现预设。候选可采用 ENet 实现、可维持客户端线上语义的兼容适配器，或目标 APK 已支持且实测通过的其他 UDP 协议。若某个 APK 只会发送 ENet，服务须向该 APK 提供兼容的线上语义，可由 ENet 库或兼容层实现。若候选要求修改 APK，单独标记适配构建与原 APK 的兼容状态，适配版结果不计入原 APK 验收。

对候选逐构建验证握手、连接状态、校验、通道或等价语义、可靠性、排序、重传、分片、重连和断线。在隔离环境记录 Linux/Windows amd64 构建、依赖许可证、运行库和客户端证据。多个候选均通过时，优先采用部署与维护成本更低的一种。不同构建需要不同线上协议时，由 transport 适配层承接，房间状态模型共用。

## 3. 组件与状态所有权

~~~mermaid
flowchart LR
    C[客户端] -->|HTTP 发现| A[api-server]
    C <-->|客户端兼容 UDP| T[transport]
    T <--> S[session]
    S <--> P[protocol]
    S <--> R[room]
    S -->|验证入房| A
    A -->|查询实时在线| H[管理 HTTP]
    H -->|读取状态快照| R
~~~

| 目录 | 责任 |
| --- | --- |
| cmd/server、internal/app、internal/config | 配置校验、依赖组装、监听与退出 |
| internal/transport | 持有 UDP 监听与客户端连接，输出带连接代次、channel 和可靠标记的事件，负责发送和断开 |
| internal/protocol | 包头、版本候选匹配、包与快照编解码，输出类型化消息 |
| internal/session | JoinGame 时限、认证请求、连接代次与会话状态 |
| internal/room | 串行拥有玩家索引、房间、关卡、快照窗口和广播目标 |
| internal/api | 本机健康检查及受保护的内部查询 |

UDP 传输实例由单一事件循环操作，房间状态由一个循环串行修改。认证使用有界并发，结果携带 peer 与连接代次返回 session。断线或超时后丢弃迟到结果。跨循环传递不可变消息，管理查询读取状态快照。有界队列满时丢弃可替换的旧移动更新。可靠控制消息无法排队时记录原因并关闭相关会话，避免静默跳过状态变化。

## 4. 服务间合同草案

接口名称和字段为拟议合同。认证凭据的线上映射需在第一阶段用客户端样本定稿。

| 方向 | 合同与行为 |
| --- | --- |
| 客户端 → API | 保留发现和好友入房接口的客户端响应结构。API 公告客户端可达的 IPv4 与 UDP 端口。分配记录表示最近一次路由选择 |
| room → API | 私有 POST /internal/v1/room/admissions/verify。请求携带 room 实例标识、声明的账号标识、已证实的凭据载体及绑定参数。成功返回 API 确认的账号标识与入房有效截止时间。HTTP 400 表示格式错误，401/403 表示凭据或权限拒绝，503 或超时表示验证不可用 |
| API → room | 私有 POST /internal/v1/room/presence/query。按已获好友查询权限的账号 ID 查询，返回在线标志、实例与可加入状态，可附路由所需房间标识。查询失败时在线状态未知，API 不以历史分配推断在线 |

内部端点同机绑定回环，跨主机使用受限网络、TLS 与独立服务凭据。服务凭据由部署注入。API 拥有入房凭据核验与账号权限判断。凭据必须能绑定当前账号、有效期和目标服务。同一凭据的重试、重放和重连语义在载体验证后定稿。首先追踪发现响应到实际 JoinGame 的字段传递。如果客户端能回传经过验证的分配证明，优先复用兼容字段承载短期证明。若没有可用回传载体，认证入房阶段暂停，评估适配客户端或兼容握手后再继续。UUID、源地址和现有发现签名均不能独立充当认证凭据。

房间循环在提交入房前复查凭据截止时间。进入 Active 后，独立的会话空闲计时由当前会话有效包刷新，断线或空闲超时即回收。API 失联时拒绝新入房，已有会话继续按本地规则运行。运行中封禁即时生效留待后续合同定义。在线由当前已入房会话生成，断线同步移除。按需查询，API 不缓存正向在线结果。API 先验证好友权限，再按可加入结果指向目标实例的配置公告地址。在线玩家可能暂不可加入，room 以入房时的容量与 profile 重新判定。room 停机或查询超时后，好友进房使用现有协议允许的失败响应，客户端表现需联调复核。

## 5. 入房、广播与过图

~~~text
Connected → AwaitJoin → Verifying → Admitting → Active
任何阶段超时或断线 → Closing → Closed
Active 内部 → Transitioning → 提交或取消 → Active
~~~

1. 传输握手完成后只分配受限的待认证状态，启动入房时限。校验帧长度、方向、channel 和字段边界，然后从包头、JoinGame 布局和构建指纹确定唯一 profile。未知或歧义时拒绝并记录原因。profile 每次连接固定，APK 名称和 HTTP User-Agent 仅供排查。
2. 认证成功后由房间循环原子检查账号、容量及关卡。对仍有效的同账号会话保留旧连接并拒绝新连接。旧会话释放后允许重连，新连接获得独立代次和初始快照。待入房期间重复 JoinGame 不增加验证任务。
3. 按接收端 codec 编码 EnterGame。传输层接受 EnterGame 入队后提交成员关系，再通知既有玩家。同一连接的后续同步排在 EnterGame 之后。入队失败时回收预留，异步发送失败走统一离房流程。场景进入由客户端验收确认。名册范围、玩家通知包、快照布局和 channel 按实际 profile 验证。广播目标按房间与协议兼容键隔离，移动和关卡状态再按关卡筛选。客户端输入只能更新自身当前会话，快照 ACK 仅推进本 peer 当前窗口。
4. 自然过图按 profile 确定 LevelUpdate、MoveResult 和 CancelMove 的顺序。房间循环验证当前代次、迁移序号及目标，确认后一次更新关卡索引及可见集，并使旧关卡快照失效。取消或超时保留原关卡。重复和迟到的确认不得重放迁移。涉及分房、合房或跨房间转移时，依旧服务证据登记源房、目标房、客户端确认和断线恢复语义。覆盖表确认存在跨实例行为时，一并定义并验证该流程。
5. 断线、发送失败和服务退出共用幂等回收路径。仅当前有效成员触发一次离开通知，同时释放在线身份、关卡索引和快照窗口。

## 6. 配置、观测和部署

使用 room-server 独立配置，建议沿用重构设计的 config/realtime.json。配置包含 UDP 绑定、管理绑定、API 内部地址、实例标识、凭据引用、连接/玩家限额、入房与验证时限、最大应用帧、队列与快照窗口大小。API 继续用 room_host 与 room_port 公告地址。具体值由技术验证和配置校验定稿。旧服务的 UDP 25565、2 channel、32 peers、6000 ms 与 16384 字节仅作为对照基线。

按配置校验、打开监听、启动循环的次序启动。任一监听失败时关闭已创建资源并退出。收到停止信号后拒绝新连接，取消待认证请求，按时限回收会话并关闭 UDP 传输与管理 HTTP。/healthz 表示进程存活，/readyz 表示本地监听及房间循环可接收连接，另行记录认证依赖状态。

日志和计数覆盖 传输握手、JoinGame 解析、认证结果、入房、断线、过图、发送拒绝与队列丢弃。用错误分类和 profile 排查，避免以账号或 peer 作为指标标签。字节样本只在隔离测试中登记，记录版本与 SHA-256、方向、channel、可靠标记、原始长度、脱敏数据及预期解释。原始会话与密钥不得入库或写入常规日志。注明脱敏是否改变校验字节，黄金样本和原始采集证据分别管理。

切换前分别验证两个服务及公告地址。回滚时将 API 公告切到独立部署且已验证的旧服务地址，客户端需重新发现并连接。内存房间不会迁移。共同占用端口时先停新服务再启动旧服务，核验监听后观察发现、握手和入房日志。

## 7. 一次性交付验收

内部开发可按传输验证、协议迁移、玩法实现和整体验收组织。上线以统一验收为门槛，覆盖表中任何承诺项缺失、失败或未验证时，保持待交付状态。

| 验收项 | 通过条件 |
| --- | --- |
| 传输与协议 | 每个目标构建完成真实客户端连接与重连，锁定线上指纹及各消息的方向、编码和传输语义。全部纳入范围的 codec 有黄金样本或可复现的旧实现差分用例 |
| 账号与入房 | 真实客户端验证发现、握手、JoinGame 解析与认证、EnterGame、进入场景和时钟同步；覆盖凭据失效、API 不可用、重复连接和重连 |
| 全量玩法 | 对覆盖表逐项验收，包含双端可见、移动与关键 GameMsg、快照 ACK、权威交接、断线清理、自然过图及旧服务具备的房间流转。对照旧服务验证协议族和房间隔离 |
| 多版本 | 0.1.8 与 0.3.11 用记录了 SHA-256 的实际 APK 独立完成上述用例。旧服务其余支持构建逐项记录自动化和实机证据，缺失的证据保留为待验收项 |
| 服务与发布 | 两服务独立构建和启停，验证好友在线、两种依赖停机、端口冲突、关停回收、公告地址切换与回滚。满足上述所有项目后统一切换 |

单元验证覆盖黄金字节正反向、异常长度、计数边界、未知 profile、迟到认证与重复断线。集成验证在对应 Go module 中执行，优先使用现有 WSL 工具链。记录 Git 状态、APK 散列、设备与 ABI、配置、地址、命令、日志时间和结论。发现接口成功、传输握手、认证入房、进入场景、同步及各玩法分别记录通过、失败或未执行。

当前设计未执行服务与客户端测试。待验证事项包括全量覆盖表、各构建实际线上协议与传输候选、发布依赖，以及可核验的入房凭据载体。
