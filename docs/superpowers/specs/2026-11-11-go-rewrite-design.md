# LaServer Go 重构设计（待评审）

## 意图与已确认方向

解决业务逻辑分散、数据写入规则不一致和多运行时启动繁琐的问题。用户已选择最终全 Go、分阶段迁移：先游戏 API 与管理功能，后实时联机。本文件细化该方向，实施前需要用户审阅。

## 方案比较

1. 分阶段全 Go：选择此方案，以兼容验收控制风险；业务 API 和实时联机最终均使用 Go，保持独立启动与部署。
2. 一次性重写全部模块：故障面过大，不采用。
3. Go API 长期搭配 Node.js 联机：迁移快，但无法消除双运行时维护，不作为最终方案。

## 架构提案

- 同一仓库、一个 Go module、两个独立服务入口：`game-api --config config/game-api.json` 与 `realtime-server --config config/realtime.json`。业务 API 内部按业务模块组织并承载管理接口，实时服务负责 ENet 与房间状态。两者分别构建、启动、停止和部署，不要求同时启动或同进程运行；迁移期实时端仍可使用旧 Node.js 实现。
- API 下发配置的实时服务可达地址；自身启动不依赖实时服务已在线。管理端独立展示实时端在线、离线或不可达状态；查询实时状态使用有超时的管理 HTTP，不跨进程调用内存对象。实时端启动同样不等待 API 在线；具体会话认证和运行时依赖依据 M0 协议证据确定，依赖不可达时明确失败，不绕过校验。
- HTTP 使用 net/http；业务包按 account、social、inventory、quest、room 划分。handler 负责协议转换，service 负责规则与事务，repository 负责 SQL。模块不得绕过其他模块 service 写其数据。
- 数据访问采用 database/sql，最终数据库明确使用 SQLite，不引入 Redis 或 MySQL，也不规划数据库换型；驱动经平台和构建验证再锁定。迁移采用有版本的 SQL，显式执行，启动只检查版本，不静默修改真实数据库。实时房间状态保存在实时服务内存中，由该服务管理生命周期；持久化业务数据由业务 API 负责。
- 管理功能通过独立鉴权的管理 API 调用业务服务，不允许浏览器或桌面端直写数据库。拟采用 Go 模板和少量原生 JavaScript，静态文件使用 embed；本阶段不引入 Node.js 前端构建链。
- 配置使用 JSON 和环境变量覆盖敏感字段，启动时检查端口、数据库、证书和配置；日志使用 slog。对外 HTTPS 方式必须经过目标旧客户端验证，不能假定其支持现代 TLS 默认设置。
- 每个服务独立通过 context 管理生命周期；启动失败撤销本服务已启动的监听器；收到终止信号后释放本服务资源，不停止另一个服务。
- ENet 传输与游戏协议分离；按协议族和具体构建做适配。房间状态由明确的单一所有者串行修改，禁止多个 goroutine 无约束写共享状态。

## 兼容与迁移约束

- 保留 HTTP 路径、字段类型、缺失字段、错误语义和二进制协议行为；不得直接把旧 Socket.IO 或 MQTT over WebSocket 当成普通 WebSocket。
- 现有 0.1.8、0.3.11 适配包均上报 0.13.4.170388，验收必须记录实际 APK，不能只按上报版本判断兼容。
- 优先以这两个适配包形成最小登录、读取存档、获取房间地址、进房和双端同步闭环；这是实施者提案，不代表旧版本已经通过验证。其他协议族后续分批迁移，不承诺扫描范围全部可用。
- ENet 库先做隔离兼容验证，核对校验和、通道、可靠传输、分片、重连与实际客户端。CGO 与纯 Go 选择以证据决定；验证前不承诺无动态库的单文件交付。
- 旧 instance 与 legacy 数据库分别盘点和迁移，不合并；使用副本验证，旧服务保持可回退。切换采用停止写入、备份、迁移、核验、启用新服务，禁止无设计的双写。
- 共存期默认按独立测试实例验收完整业务闭环，不对同一账号拆分新旧写入入口；未迁移业务继续使用旧实例。对外切换前必须完成目标闭环全部依赖，若确需按路由切换，先补充数据所有权和路由设计再评审。
- 新服务产生写入后，回退必须先保存新数据并验证回迁兼容性，不能直接恢复旧备份并称为无损回退。
- 不复制旧 Git 历史、数据库、证书、账号、原始抓包或客户端资源到公开仓库。静态响应和资源需检查敏感性及再分发权限，未确认则外置。

## 非目标与失败条件

第一阶段不进一步拆分业务微服务，不引入 Kubernetes 或自研 ENet。整个重构不引入 Redis、MySQL 或其他数据库服务，不要求一键同时启动两个服务。启动简单不能以丢失存档、削弱管理鉴权、隐式覆盖文件或虚报兼容为代价。

## 验收与待实施决策

按阶段验收，不设未经测量的性能数字。每阶段有可重现命令、隔离数据、真实结果及未覆盖项；测试运行须遵循用户授权规则。Go 工具链版本、SQLite 驱动和 ENet 库在对应技术验证后锁定。目标平台提案为 Windows amd64 与 Linux amd64；开发优先复用 WSL 环境。

源码、配置、可变数据分离；日志放 logs/，图片放 pic/，报告放 json/，脚本放 scripts/<功能>/，发布文件放 dist/<版本>/。旧项目未提交改动保持原样。Git commit/push 需要明确授权。
