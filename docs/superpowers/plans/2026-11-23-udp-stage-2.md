# UDP 第二阶段实施计划

依据 [UDP 房间服务设计](../specs/2026-11-23-udp-room-server-design.md)及[第一阶段记录](2026-11-23-udp-stage-1-results.md)。

1. 在 Windows Go 1.26.0 上先建立 0.1.8 的时钟 codec 回归用例。覆盖两种客户端头、显式布局、错误包长度和服务端 Pong 字节。样本基于旧源码和实测帧长度合成。
2. 实现独立配置、运行生命周期及传输边界。0.1.8 的候选必须通过实机 ENet 握手，0.3.11 的传输需求保持待实测。传输未完成时不发布伪造健康的入口。
3. 按第一阶段清单迁移各版本包头、JoinGame、控制包、GameMsg 和快照。为每个 profile 追踪旧实现差分结果。
4. 根据客户端回传证据定稿凭据载体后再接入 API 验证和会话。覆盖超时、重复连接、迟到认证、断线及依赖不可用。
5. 全量协议实现完成后执行各版本的实机协议验收。按项目规则单独确认测试和提交。

## 当前实现和验收边界

Windows Go 单元测试已覆盖配置、应用启停与部分启动失败回收、Ping/Pong、EnterGame、JoinGame 指纹、LevelUpdate、玩家加入/离开/换关通知与移动结果/取消。JoinGame 当前仅识别已移植的两字节头指纹，六字节头和完整 JoinGame 负载仍待迁移。0.15.5 的指纹只识别引擎，关卡字段另行解析。应用运行层要求注入已绑定的传输。会话登记已覆盖连接代次、认证并发结果过期、重复账号、容量与断线清理。

Windows 上已用 Visual Studio 2022 Build Tools 从已安装的 sky-enet 0.1.5 附带源码构建 enet.dll。构建产物留在 tmp/room-enet-native，未固定为生产依赖。已实现 Windows amd64 Go 传输绑定，并与旧 Node 客户端完成两通道、4096 字节可靠包及断线回环。实测 0.1.8 在 Windows Go 适配器完成 ENet 握手，Go 解析 channel 0 可靠 JoinGame，识别 sky0134，线上版本为 284/542/170388，观测包长 1939 字节。日志为 logs/room-server/stage-2-all-go-test-20261123.log。Linux 构建和 0.1.8 的真实客户端认证入房仍待完成。旧 Node 服务为现有的实际客户端对照。

0.1.8 实测把发现响应的 signature 完整解码为 32 字节并放在 JoinGame 帧偏移 18。帧中 UUID 和隔离测试 API 的最近分配账号相符。已接入 120 秒的签名凭据，绑定账号、当前登录会话和公告房间。API 定向合同测试及 room 全套自动化测试通过，两项 Windows 服务均可构建。全量 GameMsg、快照、双端状态、过图和房间流转保持待开发。

## 0.3.11 实机入房回归

2026-11-23 的 MuMu 验收使用 `com.tgc.sky.android311`（arm64-v8a）和独立 SQLite。0.3.11 测试包仅调整 API 地址，签名和 ZIP 对齐验证通过，安装后的 SHA-256 与归档一致。首次创建账号和冷启动后登录均成功，房间发现与入房凭据核验各成功两次。两次均观察到客户端连接 Go UDP 房间、收到 `EnterGame` 并加载或进入 `SkyHub2`。隔离库记录一个账号、两条房间分配。APK 摘要、日志与验收边界见[实际 APK 兼容矩阵](../../client-compatibility.md)。
